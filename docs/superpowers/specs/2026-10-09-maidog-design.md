# maidog design

Date: 2026-10-09
Owner: dynaum (GitHub personal account)
Status: approved for planning

## Problem

AI coding agents write Mermaid diagrams into markdown files. Inside herdr, the
`herdr-file-viewer` plugin renders markdown through an external command (glow by
default) and shows ```` ```mermaid ```` blocks as raw code. The viewer strips every
escape sequence except SGR color, so images (Kitty, Sixel) never reach the screen.
herdr core closed its Mermaid request (#1680, not planned). The viewer closed its image
preview PR (#157, unmerged).

## Solution

`maidog` is a markdown filter. It reads markdown on stdin, replaces each Mermaid
fence with a Unicode box-drawing diagram inside a ```` ```text ```` fence, and writes
the result to stdout or pipes it into a downstream command such as glow.

One repo ships three things:

1. **CLI** (`maidog`): the filter. Works with herdr-file-viewer, glow, `less -R`, bat,
   or any markdown tool.
2. **herdr plugin** (`herdr-plugin.toml` at repo root): installs the CLI with
   `herdr plugin install dynaum/maidog`, wires the file viewer with one action, and
   offers a popup preview.
3. **Docs**: a marketing README plus per-surface guides.

## Requirements

### CLI

- R1. Replace fenced blocks whose info string starts with `mermaid` (case-insensitive),
  backtick or tilde fences, 3+ characters, up to 3 spaces of indent (CommonMark).
- R2. Leave Mermaid fences nested inside a longer outer fence untouched (docs that show
  Mermaid source).
- R3. Normalize flowchart syntax before rendering to dodge upstream parser bugs:
  - spaces around arrows (`A-->B` → `A --> B`), beautiful-mermaid #140
  - no space between arrow and `|label|`, beautiful-mermaid #155
  - drop `<b>`, `</b>`, `<i>`, `</i>`, `<br>` tags in labels, beautiful-mermaid #137
  - never change text inside quotes or node brackets
  - drop a leading YAML frontmatter block (`---` … `---`) and `%%{init: …}%%`
    directives when the renderer rejects them
- R4. Fallback: on parse error, unsupported diagram type, or size cap breach, keep the
  original block and add a one-line blockquote note naming the reason.
- R5. Strip C0 control characters (except tab and newline) and DEL from diagram source
  before rendering.
- R6. Size cap: skip blocks over 300 lines or 20,000 characters (note explains why).
- R7. Options: `--ascii`, `--max-width <cols>` (0 = no limit, wider diagrams fall back),
  `--padding-x <n>`, `--padding-y <n>`, `--version`, `--help`.
- R8. Downstream command: everything after the first non-option argument (or after
  `--`) is a command that receives the transformed markdown on stdin and inherits
  stdout and stderr. maidog exits with its exit code. A missing command prints
  `maidog: command not found: <name>` and exits 127.
- R9. Subcommand `maidog herdr setup|refresh|preview` (see plugin section).
- R10. Whole run for a typical doc (10 diagrams) stays under 1 second. The viewer kills
  renderers after 5 seconds.

### herdr plugin

- P1. Manifest id `maidog`, `min_herdr_version = "0.7.5"`, platforms linux and macos.
- P2. Build step picks a runtime: Node 18+ or Bun present → use the committed bundle
  `dist/maidog.js`. Otherwise download the release binary for the platform and verify
  its SHA-256. Fail with a clear message when neither works.
- P3. Action `setup-file-viewer`: copy the runtime into a stable directory
  (`$HERDR_PLUGIN_STATE_DIR/runtime`), copy the viewer's glow palette when found, and
  write the `markdown = ...` line into the viewer's config file. Inside herdr the viewer
  reads `$HERDR_PLUGIN_CONFIG_DIR/config.toml`, so setup resolves the directory with
  `herdr plugin config-dir herdr-file-viewer` and falls back to
  `$XDG_CONFIG_HOME/herdr-file-viewer/config.toml` or `~/.config/herdr-file-viewer/config.toml`
  when that command fails. Back up the file first. Refuse to replace a non-maidog `markdown` line unless the
  user re-runs with `--force` (documented). Report the result through
  `herdr notification show`.
- P4. Startup hook `refresh`: when setup ran before, re-copy runtime and palette so
  plugin updates reach the viewer after the next server start. Install folders change
  on every update, so the viewer config must never point inside the plugin root.
- P5. Action `preview` opens a popup pane that asks for a markdown path (readline with
  tab completion) and shows the result in glow's pager.

## Out of scope (v0.1)

- Image rendering (Kitty/Sixel).
- Gantt, pie, mindmap, timeline, and other types beautiful-mermaid lacks.
- Windows.
- Homebrew tap.

## Key facts from research

- Viewer renderer contract: content on stdin, color forced with `CLICOLOR_FORCE=1`,
  only SGR escapes kept, fixed 5 s timeout, `markdown` value tokenized with
  double-quote awareness (`"/a b/c" -x` → `["/a b/c", "-x"]`).
- Viewer default markdown command: `glow -s <viewer-root>/assets/markdown-style.json -w 0 -`
  (falls back to `-s dark`).
- herdr plugin build commands get no herdr env. Runtime commands get
  `HERDR_BIN_PATH`, `HERDR_PLUGIN_ROOT`, `HERDR_PLUGIN_STATE_DIR`,
  `HERDR_PLUGIN_CONFIG_DIR`. Popup placement exists. Marketplace lists repos tagged
  `herdr-plugin`.
- beautiful-mermaid 1.1.3, MIT, deps elkjs and entities.
